# эмулятор pinephone
эмулятор pinephone, на средней стабильности, запускает nuttx

## как работает?
код работает как театр кукол за кулисами, где есть кукловод (главная программа) и сцена (окно SFML). Вот как именно он устроен.

### 1. главная идея

программа запускает внутри себя целый телефон. она не переводит код NuttX в команды компьютера, а подражает каждому его действию. nuttx думает, что работает на реальном процессоре, но на самом деле все его шаги обрабатываются кодом.

### 2. две независимые части

код разделён на два потока, которые работают одновременно:

поток 1: эмулятор (невидимая часть)

- загружает файл nuttx в виртуальную память.

- создает "поддельный" процессор с помощью библиотеки Unicorn.

- бесконечно выполняет команды NuttX одну за другой.

- как только NuttX пытается что-то сделать (напечатать букву, включить светодиод, нарисовать пиксель), код перехватывает это действие и выполняет его в реальном мире.

поток 2: окно с графикой (видимая часть)

- рисует окно на экране компьютера.

- каждые 33 миллисекунды берёт картинку из виртуальной памяти и показывает её в окне.

- читает нажатия клавиш и отправляет их в первый поток.

### 3. как код перехватывает действия nuttx

в коде есть специальные функции - хуки. они срабатывают, когда nuttx обращается к определённым адресам памяти.

- когда nuttx печатает текст:
  он пишет байт по адресу 0x01c28000 (это адрес UART). хук перехватывает этот байт и выводит символ в терминал.

- когда nuttx включает светодиод:
  он пишет число по адресу 0x02000000. хук сохраняет это число в общую переменную, и окно перерисовывает кружки.

- когда nuttx рисует на экране:
  он заполняет байты по адресу 0x10000000 (это фреймбуфер). другой поток каждые 33 мс берёт эти байты и превращает их в картинку.

- когда nuttx ждёт нажатия клавиши:
  он читает из того же адреса UART. хук вместо реального порта возвращает символ из очереди, которую заполняют нажатия клавиш из окна.

### 4. как выполняется команда nuttx

когда nuttx вызывает команду printf("Hello"), происходит это:

1. nuttx выполняет инструкцию svc (системный вызов).

2. код видит эту инструкцию, запоминает место, где nuttx остановился, и перенаправляет его в специальный обработчик внутри nuttx.

3. nuttx обрабатывает вызов и пишет буквы в UART.

4. Хук UART перехватывает эти буквы и печатает их у вас в терминале.

5. nuttx выполняет инструкцию ERET (возврат из обработчика), и код возвращает его обратно, к месту остановки.

### 5. Главный цикл программы

**в эмуляторе:**
```text
пока не прервут:
  1. выполнить 50 000 инструкций nuttx.
  2. остановиться.
  3. если nuttx что-то написал в UART - напечатать это.
  4. если nuttx включил светодиод - запомнить это.
  5. если nuttx нарисовал кадр - обновить общую картинку.
  6. вернуться к шагу 1.
```

**в окне:**
```text
пока не закроют:
  1. проверить нажатия клавиш.
  2. если есть нажатие - отправить символ в эмулятор.
  3. взять последнюю картинку из общей памяти.
  4. показать её в окне.
  5. нарисовать светодиоды.
  6. подождать 33 мс (30 кадров в секунду).
```


### 6. что такое виртуальная память

в коде есть массив `framebuffer_shared` - это общая память между потоками. эмулятор пишет в неё картинку, а окно читает.

точно так же есть переменная `hardware_leds` - общее число, где хранится состояние светодиодов.

### 7. резюме

код - это **два одновременных процесса**, связанных общей памятью.

- **процесс 1 (эмулятор)** выполняет nuttx и перехватывает все его попытки взаимодействия с железом.
- **процесс 2 (окно)** показывает результат и передаёт нажатия клавиш.
